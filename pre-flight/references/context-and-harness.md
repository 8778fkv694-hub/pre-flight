# 上下文与执行机制

在新项目基础建立、接手丢失上下文、Agent反复失败或准备从原型走向生产时读取。先复用宿主能力，不为使用本Skill开发一套新平台。

## 项目基础宪法

与用户用普通语言梳理目的、服务对象、成功标准、非目标、不可突破的边界、AI自主范围和变更方式；目标经AI复述并由人确认后才正式纳入Intent。共同规则放 AGENT.md，详细意图和验收放其链接；草稿与已确定的决定分别记录。

宪法随有依据的决定演进，不把AI建议或沉默变成用户批准。普通实施选择可由Agent按授权处理；目标、重要取舍和权限实质变化需要相应决定。规则冲突先核对用户当前指令、来源与实际证据，保留未决；项目文件不覆盖宿主或上层权限。

## 上下文分层

六类信息各有入口：指令（AGENT）、知识（架构/领域资料）、记忆（STATUS/决定/交接）、示例（实际模式与失败样本）、工具（真实命令/接口）、护栏（运行中的检查与权限）。缺失时标未建立，不用模板补造事实。

常驻正文只留身份、关键规则、真实命令和导航。按工作包加载相关Spec、源码、数据契约和技能；不把全库、历史日志及密钥塞进上下文。任务记录引用来源和版本，过时记忆复核后再用。任务中断前保存当前包、动作结果、未决和下一步，摘要链接原证据。

## 让规则变成可验证的运行能力

在 Plan 中按任务记录以下情况：

| 面向 | 要核实的事实 |
|---|---|
| 工具 | 所需能力可用，输入/输出和失败语义清楚；运行实际最小调用 |
| 环境 | 源码、依赖、数据、网络、凭证和执行位置明确；隔离覆盖范围真实 |
| 权限 | 可读/可写/外发/发布范围和批准入口；敏感操作由真实机制约束 |
| 反馈 | 检查命令可运行，失败会返回非零/明确失败；错误传回当前工作包 |
| 可观察性 | 可定位代码/配置/模型版本、动作、输出、耗时与成本；敏感值脱敏 |
| 恢复 | 可停止、恢复和交接；未知副作用先核对，不自动重放 |

状态分别写“已实测/已配置未验/未建立/不适用+理由”。只有文档时不能写成已建立门禁。没有必要外部工具时，本地终端与可执行测试可以构成足够的执行基础。

## 从原型走向生产

Intent 中明确当前用途及真实用户/数据风险。原型可缩小范围与验证，但不能隐藏未验部分。转生产前回到Spec补齐实际业务边界、权限、错误/取消/恢复、必要的性能和运维验收，完成对应检查后才报告适用环境可交付。

确定性行为用 tests；有模型决策时再建 eval：版本化样本与独立期望、失败/越权反例、评分规则、通过线、运行配置、样本量、预算；记录重复运行的波动和失败分布。评估开发Agent时同时观察产物与必要轨迹，不能只看最后一条自报。一次demo仅证明一次结果，有限样本不证明所有情形正确。

模型、提示词、Skill、工具定义或上下文策略变化后，按受影响行为重验。模型评分先用人工/可确定样本校准，不能让同一生成结论自行充当验收。

## 花费与改善

记录从意图到已验证结果的时间、人工等待、返工、逃逸缺陷、维护投入及可获得的token/金额；拿不到的数据标未知。预算包括必要迭代与停止条件。是否换模型、拆Agent或增加自动化由同口径质量/时延/总成本证据决定。先补造成失败的上下文、工具或测试缺口，避免只追加提示词。
