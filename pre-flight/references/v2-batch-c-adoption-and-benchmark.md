# Pre-flight V2 · 批次 C：渐进采用、CI 门禁、按需加载与行为基准

状态：开发中；本批次不得未经验证直接并入 main。

## PF-09 渐进采用

- **Observe**：只读识别项目现状、已有文档/脚本、实际运行证据；不覆盖旧文件。
- **Assist**：以候选差异建议 Intent/Spec/Plan 结构，不强制创建整套文件；人决定是否采用。
- **Enforce**：项目所有者明确启用后，仅对已约定的可机检契约设置阻断；语义判断仍交由人确认。
- 不根据文件缺失推断“不合规”；存量项目可有自己的命名和等价流程，先建立映射。

## PF-10 CI 严格度

| 档位 | CI 行为 | 使用前提 |
|---|---|---|
| observe | 记录发现，不阻断 | 默认，尤其存量项目 |
| warn | 输出诊断，不阻断 | 团队开始试运行 |
| enforce | 对确定性错误返回非零退出码 | 明确批准、稳定基线与回滚路径 |

不允许自动从 observe/warn 升级到 enforce；不能将人工确认、授权签名、真实 UI 验证伪装成静态 CI 检查。对旧项目不自动改写 AGENT.md 或 lock。

## PF-11 Skill 按需加载

入口 SKILL.md 只保留决策流程、停止线与索引；领域参考、示例和检查器按任务相关性加载。禁止把所有参考文件默认塞进每次 Agent 上下文；缺少某文件时先报告缺口，不自动生成“通过证据”。

## PF-12 行为基准

建立固定、可重复的样例集，评估 **遵守授权**、**Intent 复用与变更确认**、**路由正确性**、**交接恢复**、**证据真实性**、**简单任务开销**。每个样例须记录输入、期望、实际轨迹、模型/宿主版本、工具权限、运行环境、重复次数与成本。脚本单测只能证明确定性工具正确，不等于模型遵循 Skill。

## 验收与停止线

- Observe 在旧项目上只读，不能产生意外写入。
- Enforce 必须显式选择，不能由“继续”“自动优化”等模糊指令推断。
- 参考文档有按需索引，不将所有材料常驻上下文。
- 基准集区分可执行的工具级测试与尚待真实 Agent 执行的行为测试。
- 批次 C 单独 PR、独立 CI；不修改已冻结基本法。

## 已实现的命令及验收范围

- `python3 pre-flight/scripts/check_adoption.py --project /path/to/project --mode observe`：只读报告，缺失的可选模板仅提示。
- `--mode warn --contract-check`：在标准四工件齐全时调用既有确定性契约检查，但不阻断；其他布局报告不适用，不自动初始化。
- `--mode enforce --approved-enforce --contract-check`：需要显式批准开关，且仅对能确定的契约错误阻断。CLI 的批准开关**不是身份认证**，CI 仓库管理者必须自行配置受保护的工作流和分支规则。
- `pre-flight/benchmarks/v2-batch-c-scenarios.json`：六个行为基准均为 `NOT_RUN`；这不是模型评测结果。
