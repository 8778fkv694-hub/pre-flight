# 基本法修正：分层、门槛与防绕过

项目基本法指 AGENT.md 中的共同规则正文（目的、边界、权限、确认规则与修正程序）。它初始化后长期使用，既不能冻结到阻碍演进，也不能被运行中的临时要求或后续“整理”悄悄改写。本文件规定 L1 核心条款的修正门槛、讨论处理与可执行检查；项目可按规模裁剪，但 L1 的确认与记录不可省。

## 条款分层

| 层级 | 内容示例 | 修改方式 |
|---|---|---|
| L1 核心条款 | 目的与服务对象、不可突破的边界、权限与自主范围、意图确认规则、本修正程序本身 | 修正案 + 人明确逐条确认 + 版本与记录 + 修后重验 |
| L2 稳定规则 | 技术栈、真实命令、协作规则、安全与隐私要求、验收口径、当前用途 | 记录原因与影响，人知悉或确认；关联Spec/Plan重验 |
| L3 实施细节 | 目录结构、命名、临时约定、工具偏好 | 已授权范围内自主调整，随工作包记录 |

L1 条款在 AGENT.md 中写成单行条目并带稳定 ID（如 `- [BL-001] 意图设定：……`），集中在“受保护条款”说明下。没有 ID 的条目即使重要也按 L2 处理。层级、ID 与清单在初始化确认时定版，之后按本程序修改。

## 修正程序（L1，标准档）

1. **提案，不改正文。** 写候选修正案：修正案ID、条款ID、原文、修改后全文、理由、影响（Intent/Spec/Plan/验收/授权/风险）、替代方案与不修改的后果。状态 draft。
2. **AI复述。** 用普通语言复述“哪一条、从什么改成什么、有什么影响”，展示修正案全文；区分人的原话、AI理解与建议。
3. **人明确逐条确认。** 只接受点名条款与版本的明确答复；沉默、含糊的“好”、其他Agent转述、生成文件都不算。一次确认可覆盖同次展示的多条，但须记录范围。AI不得自行批准。
4. **提案与决定分离。** 讨论、提案、决定至少两步；提案后不立即执行。人当场说“就按这个改”且指向唯一已展示修正案时，可视为决定，记录其指向。
5. **版本与记录。** 修改后：基本法版本+1，记录日期、确认主体与范围；旧版保留在Git历史或不可变副本；在项目的修正记录（`docs/sdlc/maintain/basic-law-log.md`，[模板](../assets/project-template/docs/sdlc/maintain/basic-law-log.md)）登记修正案ID、条款、前后文摘要、依据与验证证据；更新哈希基线（见“防绕过”）。
6. **修后重验。** 对照Intent/Spec/Plan/实际行为检查一致性；冲突项列明并保留未决，不默认用新文替换旧证据。旧测试只能证明旧身份。
7. **紧急例外。** 安全、违法或不可逆风险可先暂停执行并标记“临时处置”，不得因此永久改写L1；事后必须补修正案完成确认或撤销临时处置。已预先批准并记录范围的应急/恢复流程不受此限。

## 讨论、提案、决定

- **讨论态**：只给选项、影响、代价与风险，不写文件、不把讨论当决定。
- **提案态**：形成候选修正案，标 awaiting-confirmation；可写候选草案，不改正文。
- **决定态**：人明确点名条款并同意，按上节程序确认、记录、改正文、重验。

运行中被打断的补充先按[引导式意图确认](intent-confirmation.md)判断类型；涉及规则或授权边界的进入本程序。讨论不是决定，提案不是生效；实现细节不借机逐步索要确认。

## 防绕过

基本法不是靠措辞郑重防绕过的，需要可执行部分：

1. **受保护清单与稳定ID**：L1条款带 `[BL-xxx]`；删除、改写或语义降级必须能被发现。
2. **哈希基线**：用技能包内 [scripts/check_basic_law.py](../scripts/check_basic_law.py) 冻结条款哈希（`--freeze --note`；修正后按修正记录 `--force --amend <修正案ID>`），之后 `--check` 比对。内容变化而基线未更新即失败，提示先走修正程序。基线文件为 `docs/sdlc/maintain/basic-law.lock.json`，随项目版本管理。
3. **版本与记录**：AGENT.md 修改记录与修正记录文件可回查；旧版保留，不覆盖历史。
4. **审核与权限**：AGENT.md 变更进入代码审查（PR/保护分支），由人批准；Agent 不得自批 L1 修正。无Git时退化为人工复核与版本副本，保障更弱，须如实标注。
5. **周期审计**：每个工作包收尾或交付前对照基本法、Intent、Spec、Plan与实际行为；发现漂移列未决，由人决定修正哪一侧，不由Agent默认改写。
6. **初始化定版与接手核对**：初始化时基本法为草稿，人确认后标 accepted v1；接手先读版本、未决修正案与最近一次检查结果。

## 限度

Skill与Markdown是指导，不是权限强制器；哈希检查也只有被实际运行（CI、hook或人工）才有效。真正的强制来自宿主：Git保护分支、PR审查、目录与权限隔离、人工批准。不能宣称仅靠文档就阻止了绕过。门槛也不宜无限拔高：过度冻结会让基本法脱离现实并诱发绕过；分层、紧急例外与事后复核让高门槛可持续。
