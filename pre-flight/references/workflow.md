# 六阶段契约

阶段是可反馈的环，不是逐级签字瀑布；按任务选择必要实践。目录名按原书阶段，文件名按产物：Stage 1 Plan → plan/intent.md；Stage 2 Design → design/spec.md；Stage 3 Build → build/plan.md。

## 1. Plan：人的意图

输入可为对话、用户问题、业务材料或维护事件。保留可定位原话与时间，归纳不得冒充直接引述。先知道对象、价值、范围、结果与约束，再谈框架和代码。无法回取的历史说法标“转述/待核实”。

退出条件：关键目标已由现有明确指令或可回查反馈确定，未决项有影响说明；资料可追溯。进入设计可以含不阻断的显式假设，不能让其变成隐含承诺。

## 2. Design：可检验的决定

Spec至少覆盖：主要用户路径、边界、领域对象、接口与数据、权限和隐私、失败/取消/离线、兼容迁移，以及适用的性能或可访问性要求。只展开项目需要的部分。条款ID关联意图和验收；预期结果要能由宿主、外部数据或用户观察核对。

UI先写人要完成什么、主要动作和状态，再定页面。空/加载/失败/窄屏/键盘等按实际产品覆盖。用真实渲染检验观感；避免把版本哈希与内部步骤塞到默认用户流程。

退出条件：未决设计不会阻断所领工作包，可指出每项如何验收。设计冻结是版本与决定记录，仍未证明实现完成。

## 3. Build：计划与实施

检查当前实现与依赖，不默认已有工程资产为零。Plan按小包列范围、输入Spec版本、验收、预算、恢复；先贯通最小可用路径，之后每步保持可运行。技术命令须从实际工程核实；新项目未知命令标“待建立”，建立后回填。

计划模式、自动模式、子Agent、MCP或并行会话都是可选实现手段，不依赖特定斜杠命令。启用前查宿主能力和授权。并行任务不共享写集合；共享数据库、设备、端口另作协调。

退出条件：候选实现、可审diff、实际验证结果齐全；不把“生成代码”当交付。已获授权的日常工作持续完成。

## 4. Test：可靠反馈

先运行与变化直接相关的检查，再扩到必要回归。缺陷需要可判别的失败样本；新功能测试行为与关键拒绝场景，不机械镜像实现。UI做视觉与交互，跨系统做各端实际结果，模型行为用冻结样本和独立判据。记录源码/隔离/产物/安装/真实业务各自边界。

失败、合法跳过、环境阻碍、未执行分别统计。缺依赖要确认具体原因；真实崩溃不能当缺依赖跳过。数值收据检查类型、有限性、范围、枚举和数据来源；不信模型自报“成功”。

模型/提示词/Skill变化按影响建立eval，真实额度先定样本与成本。CI未配置时执行本地命令并保留收据，不杜撰CI绿灯。不能将测试阈值下调使结果变绿。

## 5. Deploy：审查与交付

审查行为/安全/Spec符合性，发现写触发条件、影响和证据，不为固定轮数凑问题。发布前准备具体产物、版本、检查结果、适用授权、备份迁移与恢复；已获授权可执行，缺授权时只在该动作前请求。

部署工具、CI、hook按团队环境配置并实测。合并、发布、安装、业务验收分别记录；回读实际环境身份和健康状态。未发布的项目可交付源代码或本地预览，明确范围。

## 6. Maintain：回到下一次意图

将真实问题、用户反馈和运营指标归入候选改善，附环境、证据、影响和判断。没有稳定统计基线不套3σ阈值；无监控系统先用手工记录。经验可以改回归/说明，但改变产品目标、权限或发布策略须有相应决定。

可采用前置已批准的自动诊断/恢复流程；未建设或未授权时不自动部署、回滚或定时运行。每个重大问题留下根因已知/未知、恢复和回归，闭环到新工作项或意图修订。

## 流程收益

可量：首次正确交付率、需求返工、任务到验证成果的时间、人工等待、成本与逃逸缺陷。改进结论须同口径样本与基线；不设适用所有项目的“15秒全量测试/100%正确率”承诺。
