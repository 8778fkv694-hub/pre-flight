## 项目基本法

状态：草稿；人确认后标 accepted v1，之后只能按“修正程序”修改。初始化不代表已确认。

条款分层：L1核心条款（带 [BL-xxx] 稳定ID，见“受保护条款”）、L2稳定规则、L3实施细节；以下未标ID者为L2。

- [BL-001] 意图设定：原始表达 → AI引导梳理并复述 → 人确认该版本 → 正式Intent；保留复述与确认记录，候选不得当正式目标。
- [BL-002] 目的与服务对象：待明确，详见Intent。
- [BL-003] 做好标准与非目标：待明确，详见Spec。
- [BL-004] 核心原则与不可突破的边界：待明确；不把Agent推测当人的决定。
- [BL-005] AI可自主处理及需要人决定的范围：待核实已有授权，明确缺口。
- [BL-006] 修正程序：L1条款只能按“修正案 → AI复述 → 人明确逐条确认 → 版本与记录 → 修后重验”修改；提案与决定分离，AI不得自行批准，冲突期间按现行条款执行或暂停相关动作。
- 当前用途（L2）：探索原型/内部试用/生产目标，待确定；用途升级需重核验收。
- 中途补充（L2）：运行中被打断、收到临时补充时，不直接覆盖已确认Intent、当前有效版本或基本法；混合或判断不清时按更高等级处理。
- 补充的四类处置（L2）：澄清可继续；禁止/暂停类立即遵守并留痕；功能·范围·验收标准变更先暂停冲突动作、保留现场，再转候选Intent复述确认；规则·授权边界变更按“修正程序”处理；授权收紧/暂停/撤回立即生效，扩大/新增须明确授权并记录。

受保护条款（L1）即上述带 [BL-xxx] ID 的条目；增删改或语义降级须走“修正程序”，条款ID不得静默变化。

## 协作规则

先核对工作目录、分支、未提交改动及当前工作包；保留他人工作。人的当前明确要求优先于历史偏好，歧义与决定留痕。范围内自主实施，关键新决定才询问。并行工作明确写集合和共享资源；worktree不隔离设备或数据。

Spec冻结、实现验收、正式生效分别记录；新版本未验不得替代稳定基线。失败/跳过/未验如实披露。写后验证实际结果，效果未知先只读对账，不盲目重放。发布和生产操作核对适用授权。

项目特有规范、真实自动检查及权限边界：待团队明确。Markdown是指导，不能当已强制执行的安全机制。

## 上下文与执行基础

正文保持精简，领域知识、详细设计、示例、交接按需读取并链接来源。所需工具、环境隔离、权限、检查命令、日志/成本与恢复的已实测状态记录在当前Plan；未建立的机制如实标明。规则和技能变更与代码一起审查，按影响验证。
