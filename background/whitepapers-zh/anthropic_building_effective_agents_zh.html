1. 引言：智能体究竟是什么？ (What are agents?)

“在过去一年中，我们与数十支构建 AI 应用的工程团队进行了深入交流。最成功的团队往往并不盲目使用繁琐的通用智能体框架，而是从极简的设计模式出发，根据实际业务需求逐步演进。”
— Erik Schluntz & Barry Zhang, Anthropic

在人工智能领域，“智能体（Agent）”一词已经被广泛赋予了从完全自治的科幻实体到简单脚本的各种含义。在 Anthropic 的工程语境中，我们对“智能体系统”有着非常清晰、实用的界定：

工作流 (Workflows) 与 自主智能体 (Autonomous Agents) 的本质区分

我们将基于大语言模型的系统划分为两大阵营：

  • 工作流 (Workflows)：通过预先编写好的代码逻辑编排大语言模型（LLMs）和工具的系统。系统中的执行路径是确定性规划好的（例如顺序执行、固定分支判断）。
  • 自主智能体 (Agents)：大语言模型在其中动态主导自身的执行流程与工具使用。模型自主决定下一步是继续思考、调用某个工具，还是向用户交付结果。

增强型 LLM 架构基石 (The Augmented LLM)

一切智能体与工作流的基础，都是增强型大语言模型（Augmented LLM）。基础模型通过接入检索（Retrieval）、外部工具（Tools）以及持久状态与记忆（Memory），完成了从孤立文本生成器向现代应用核心的蜕变。

图 1：增强型大语言模型架构 (The Augmented LLM)
📊 增强型 LLM 核心组成要素
  • Retrieval (检索)：通过语义搜索或向量 RAG 获取新鲜领域知识，杜绝模型幻觉。
  • Tools (工具)：赋予模型操作物理世界的能力（执行数据库写入、调用 SaaS API、运行 Python）。
  • Memory (记忆)：维护状态机与上下文记录，使交互具备长程一致性。

2. 何时（以及何时不应）使用智能体 (When to use agents)

在构建 AI 应用时，最大的设计陷阱是“过早引入过度复杂的自主智能体架构”。许多团队误以为必须使用复杂的 Agent 框架才能交付高价值应用。然而实践证明：

💡 架构极简演进法则

从最简单的单个 Prompt 开始：如果单次提示词能解决，绝不引入多步调用；如果需要外部数据，优先接入 RAG；如果逻辑涉及清晰的分步环节，优先编写确定性工作流 (Workflows)；唯有在任务充满高度动态不确定性、解题步骤无法提前穷举时，才引入自主智能体 (Autonomous Agents)。

智能体的引入是一场工程权衡：自主智能体带来了处理开放性未知问题的惊人灵活性，但其代价是延迟更高、Token 成本成倍增加，以及系统可预测性与可复现性大幅下降。因此，绝大多数高可用商业系统，其骨架是由确定性工作流构成的，仅在局部最具挑战的节点挂载特化智能体。

3. 智能体的五大核心工作流模式 (Common Workflow Patterns)

Anthropic 总结提炼出了业界最通用、最经过实战验证的五大核心基础模式：

模式一：提示词链 (Prompt Chaining)

将一个复杂庞大的任务，按顺序拆解为若干个线性排列的子步骤。每一个 LLM 调用处理前一步的输出，并在关键节点设置“质量门禁关卡（Gates）”进行有效性核验。

图 2：提示词链工作流 (Prompt Chaining Workflow)

模式二：分类路由 (Routing)

由一个专职的分类器（轻量 LLM 或嵌入模型）判断用户意图，并将请求精准分流到专门针对该任务定制的特定工作流或专家模型中。

图 3：分类路由工作流 (Routing Workflow)

模式三：并行化 (Parallelization)

当任务可以拆解为互不依赖的子任务时，同时并行触发多个 LLM 调用。主要分为两种典型子形式：

  • 分块并行 (Sectioning)：例如同时并发分析十份独立的文档，最后聚合汇总。
  • 多视角投票 (Voting)：对同一个高难度复杂逻辑，并发触发不同系统指令或温度系数的模型生成候选解，由裁决机制择优录取。

模式四：编排者-工作者模式 (Orchestrator-Workers)

由一个顶层的“中央编排者 LLM”全面审视宏观目标，在运行时动态推演需要哪些子任务，并将子任务分派给多个“工作者 LLM（Worker LLMs）”执行，最后对工作者的返回结果进行归纳合成。非常适合于任务无法提前预知固定步骤的复杂研究与工程落地场景。

模式五：评估者-优化者模式 (Evaluator-Optimizer)

构建严格的闭环自我迭代回路：由一个“生成者 LLM”起草方案，而独立的“评估者 LLM”对照评分规则进行苛刻核验。如果未通过，评估者给出详细缺陷反馈，驱动生成者持续重构修改，直至达标。

4. 全自主智能体 (Autonomous Agents)

当我们在主循环中将环境观察结果（Observations）与可用工具完整交给模型自主调度时，系统就迈入了全自主智能体阶段。典型标志是类似 Claude Code 或 SWE-bench 求解器：智能体面对一个开源 GitHub 仓库的 Issue 报障，能够自主执行：

  1. 使用 grep 和 file_search 工具浏览代码库；
  2. 推断潜在 Bug 根因并定位出出错的若干文件；
  3. 自主编辑修改文件；
  4. 在命令行沙箱中运行项目的自动化测试用例；
  5. 捕获单测报错，反思并重新修改代码，直至测试完全通过；
  6. 最后自动创建 Pull Request 并交付人类审查。

5. 智能体工程落地三大黄金法则 (Engineering Principles)

Anthropic 总结了构建高可靠工业级智能体的三大基石守则：

  1. 极致追求架构极简 (Simplicity First)：永远不要为了使用炫酷的多智能体概念而复杂化系统。多引入一层智能体，就多增加了一层不确定性与潜在故障点。
  2. 严守接口透明度 (Transparency & MCP)：清晰定义工具的输入输出契约。采用类似 Model Context Protocol (MCP) 这样的开放标准，确保工具对模型可解释、易发现。
  3. 严密的人在回路安全底线 (Human Oversight)：在涉及资金、删除数据或对外部产生永久物理影响的边界上，必须设置强制断点，由人类工程师把关确认。

6. 结语：大道至简的架构艺术 (Conclusion)

在 AI 智能体的大航海时代，最优秀的架构师从来不是那些堆砌最多智能体概念的人，而是那些深刻理解大模型能力边界、用最少的不确定性解决实际商业问题的工程大师。掌握提示词链、路由、并行化、编排者以及评估反馈回路，你便拥有了打造现代生产级智能系统的最坚固武器库。
